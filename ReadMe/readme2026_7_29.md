TCP 多线程服务器学习总结

一、TCP 与 UDP 区别

UDP

UDP 面向无连接。

特点：

不需要建立连接

不保证可靠传输

不保证顺序

速度快，开销小

主要接口：

socket
sendto
recvfrom

TCP

TCP 面向连接。

特点：

三次握手建立连接

可靠传输

保证数据顺序

有连接状态

通信流程：

Server:

socket
  |
bind
  |
listen
  |
accept
  |
recv/send


Client:

socket
  |
connect
  |
send/recv

二、TCP核心接口

socket

创建通信端点：

socket(AF_INET, SOCK_STREAM, 0);

返回文件描述符。

bind

绑定服务器IP和端口：

bind(sockfd, sockaddr, sizeof(sockaddr));

告诉系统：

这个socket负责哪个地址的数据。

listen

让socket进入监听状态：

listen(sockfd, backlog);

listenfd只负责等待连接。

accept

接受客户端连接：

clientfd = accept(listenfd,...);

为什么需要accept？

因为服务器有两个职责：

等待客户端连接

与客户端通信

所以：

listenfd:

等待连接


clientfd:

数据通信

recv/send

TCP通信使用clientfd：

recv(clientfd,...)

send(clientfd,...)

三、TCP多客户端模型

单客户端：

server

只能服务一个客户端。

recv/send recv/send recv/send

四、pthread与TCP结合

pthread入口函数要求：

void* Function(void*)

成员函数不能直接作为入口，因为成员函数需要this指针。

解决：

使用static：

static void* ThreadFunction(void* arg)

五、this指针传递

创建线程：

pthread_create(...,(void*)this);

线程恢复：

TcpThread* tt=(TcpThread*)arg;

然后：

tt->Receive();

tt->Send();

六、TcpThread设计

一个客户端对应一个TcpThread对象。

成员：

clientfd

tid

负责：

Receive()

Send()

线程执行函数

七、对象生命周期

错误：

TcpThread thread(fd);
thread.Init();

线程运行时对象可能已经销毁。

正确：

动态创建：

TcpThread* thread =
new TcpThread(fd);

保证线程运行期间对象存在。

八、detach与join

join：

等待线程结束。

服务器不能等待每个客户端线程，否则无法继续accept。

detach：

pthread_detach(tid);

线程结束自动释放资源。

适合服务器模型。
