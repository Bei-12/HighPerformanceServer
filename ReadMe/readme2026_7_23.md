# ThreadPool线程池实现

## 一、第三阶段目标

前面已经完成：

- Mutex互斥锁
- Condition条件变量
- BlockingQueue阻塞队列
- Producer Consumer模型


第三阶段目标：

实现一个完整线程池。


线程池解决的问题：

> 不需要每次任务到来都创建线程，而是提前创建一批线程，让线程不断从任务队列中获取任务并执行。


---

# 二、线程池整体设计思路


线程池主要由四部分组成：

```
              Task
                |
                |
        BlockingQueue
                |
        ----------------
        |      |       |
      Thread Thread Thread

                |
                |
           ThreadPool
```


各模块职责：

|模块|作用|
|-|-|
|Task|描述一个任务|
|BlockingQueue|保存等待执行的任务|
|Thread|工作线程|
|ThreadPool|管理所有线程|



---

# 三、为什么需要线程池


## 1. 普通创建线程的问题


如果每个任务：

```
任务到来

↓

创建线程

↓

执行任务

↓

销毁线程
```


问题：

1. 创建线程有成本

2. 大量线程竞争CPU

3. 线程生命周期不好管理

4. 资源浪费


所以：

提前创建线程。

```
创建线程

↓

等待任务

↓

执行任务

↓

继续等待任务

```


---

# 四、Task任务设计


## 为什么需要Task？


线程本身不知道任务内容。


例如：

任务1：

```cpp
打印数据
```


任务2：

```cpp
计算结果
```


线程不应该关心。


所以抽象：

```
Thread

负责:

获取任务

执行任务


Task

负责:

具体工作
```


---

# 五、Task设计


使用：

```cpp
function<void()>
```


保存任务函数。


结构：

```cpp
class Task
{

private:

function<void()> _func;

bool _exit;

};
```



---

## Run执行任务


```cpp
void Run()
{
    if(_func)
        _func();
}
```


线程只需要：

```cpp
task.Run();
```


---

# 六、为什么需要退出任务


Worker线程：

```cpp
while(true)
{

Pop(task);

task.Run();

}
```


问题：

线程不知道什么时候退出。


所以设计特殊任务：

```
Exit Task
```


当线程获取：

```cpp
task.IsExit()
```


退出循环。

# 七、BlockingQueue阻塞队列


## 作用


线程池内部：

```
Producer

提交任务


↓

BlockingQueue


↓

Consumer

执行任务
```



---

## 为什么需要阻塞


如果没有阻塞：

```cpp
while(queue.empty())
{

}
```


线程会一直查询。


造成：

- CPU浪费
- 无意义轮询


所以：

任务为空：

```
等待
```


任务进入：

```
唤醒
```

# 八、Condition条件变量


BlockingQueue需要两个条件。


## 1. notEmpty


表示：

```
队列不为空
```


作用：

唤醒消费者。


例如：

```
Producer Push任务

↓

Signal()

↓

Consumer执行
```


---

## 2. notFull


表示：

```
队列没有满
```


作用：

唤醒生产者。


例如：

```
队列满

↓

Producer等待

↓

Consumer取走任务

↓

Signal()

↓

Producer继续生产
```


---

# 九、Push生产任务


流程：

```
加锁

↓

判断队列是否满

↓

满:

等待notFull


↓

插入任务

↓

唤醒Consumer

↓

解锁
```



代码思想：

```cpp
Push(Task task)
{

_mutex.Lock();


while(queue.size()>=capacity)
{
    notFull.Wait();
}


queue.push(task);


notEmpty.Signal();


_mutex.Unlock();

}
```



---

# 十、Pop消费任务


流程：


```
加锁

↓

判断队列为空

↓

为空:

等待notEmpty


↓

获取任务

↓

删除任务

↓

唤醒Producer

↓

解锁

```



代码思想：

```cpp
Pop(Task& task)
{

_mutex.Lock();


while(queue.empty())
{
    notEmpty.Wait();
}


task=queue.front();

queue.pop();


notFull.Signal();


_mutex.Unlock();

}
```

# 十一、Thread工作线程设计


Thread负责：

1. 创建pthread

2. 等待任务

3. 执行任务


---

线程入口：

```cpp
static void* ThreadRoutine(void* arg)
{

BlockingQueue<Task>* BQ =
(BlockingQueue<Task>*)arg;


while(true)
{

Task task;


BQ->Pop(task);



if(task.IsExit())
{
    break;
}


task.Run();


}


return nullptr;

}
```

# 十四、线程池启动


创建线程：


```cpp
ThreadPool(int num)
{

for(int i=0;i<num;i++)
{

_workers.push_back(
Thread(i,&_queue)
);

}

}
```



启动：


```cpp
void Start()
{

for(auto&t:_workers)
{
    t.Start();
}

}
```

# 十五、提交任务


Submit只负责生产。


正确：

```cpp
void Submit(Task t)
{

_queue.Push(t);

}
```


错误：

```cpp
_queue.Push(t);

_queue.Pop(t);

```


原因：

Submit是Producer。


如果Pop：

```
主线程提交任务

↓

Push

↓

Pop

↓

任务消失


Worker没有任务
```


---

# 十六、线程池停止


## 为什么需要Stop?


Worker：

```cpp
while(true)
{

Pop();

}

```


无法自动退出。


所以：

发送退出任务。


---

## Exit数量问题


如果：

```
5个worker
```


必须：

```
5个Exit Task
```


否则：

```
worker1退出

worker2等待

worker3等待

worker4等待

worker5等待

```


Join会一直等待。



---

代码：

```cpp
void Stop()
{

for(int i=0;i<_workers.size();i++)
{

_queue.Push(Task::Exit());

}



for(auto&t:_workers)
{

t.Join();

}


}
```

# 十七、实现过程中遇到的问题


## 问题1：线程池没有输出


现象：

```
Submit task
Submit task
```

但是没有：

```
Thread execute
```


原因：

```cpp
vector<Thread> _workers;
```


为空。


Start():

```cpp
for(auto&t:_workers)
```


执行0次。


解决：

构造函数创建worker。


---

## 问题2：Submit后任务消失


原因：

Submit里面：

```cpp
Pop()
```


Submit不应该消费任务。


解决：

只：

```cpp
Push()
```


---

## 问题3：Stop卡死


原因：

只发送一个Exit任务。


解决：

发送：

```
worker数量
```


个Exit。
