## 🐦 Mistakes & Debugging Lops
### 1.Mistake: 
      (1) What should be the order of fork() and pipe()? Forking before pipe will cause parent and child processes to not share the same pipe.
      (2) Why do we need to close one end of a pipe after creating it? Not shutting it down will result in wasted resources and failure to reach EOF
      (3) Why is vector<Worker> vw(4) not suitable? Four objects have already been precreated; pushing then later will increase the number to eight
      (4) Why can't a child process access data subsequently pushed in by the parent process? The address space has already been copied during the fork operation
      (5) Why can't the child process read the data? Read/Write terminal save error
      (6) atoi(child) returned an incorrect result? No string teminator was transmitted in the pipe
      (7) Why does 'write(...,"-1",2)' fail to exit? What was actually sent was '-' and '-1', without a terminator
      (8) Why do we need to check the return value of read()? Without judgement, the state of the pipeline can't be known
      (9) Why does read() block? The pipe is empty, but the write end still exists
      (10) When does 'read()==0' occur? When all write ends are closed
      (11) Why do we need to close al write ends when exiting? Otherwise, the child process will never receive the EOF message
      (12) Where should child process recycling be performed? Placing it in a task loop will cause it to block prematurely
      (13) Why can only parent-child communication be achieved? An anonymous pipe is unidirectional
      (14) How to achieve two way communication? Anoymmous pipes are inherently unidirectional
      (15) Why can't multiple child processes share an anonymous pipe? Unable to precisely control the target of task delivery
