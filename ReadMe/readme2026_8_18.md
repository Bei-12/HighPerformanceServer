# 阶段六：Reactor模型实现总结

## 一、阶段六目标

阶段五完成了基于epoll的非阻塞服务器：

    epoll_wait()
        |
        fd
        |
    if判断
        |
    Read/Write

但是这种方式存在问题：
-   fd只是一个数字，无法表示连接状态
-   事件处理和业务逻辑耦合
-   连接数量增加后代码难维护

阶段六目标：
从：
> 面向fd编程
转变为：
> 面向对象事件驱动编程

整体结构：

    TcpConnection
           |
           |
        Channel
           |
           |
        Poller
           |
           |
        epoll

------------------------------------------------------------------------

# 二、三个核心对象

## 1. Poller
职责：负责封装epoll。
它只负责：
-   等待事件
-   找到发生事件的Channel
不负责：
-   recv
-   send
-   业务处理

流程：
    epoll_wait()
    返回fd
    ↓
    找到Channel
    ↓
    交给Channel处理

------------------------------------------------------------------------

## 2. Channel
职责：一个fd在Reactor中的管理对象。
保存：
``` cpp
int fd_;
uint32_t events_;
uint32_t revents_;
function<void()> callback;
```

其中：
### events\_
表示：
> 希望内核监听什么事件

例如：EPOLLIN 表示监听读事件。

发送数据：EPOLLIN | EPOLLOUT 表示监听读写。

### revents\_
表示：
> 实际发生了什么事件

流程：
    epoll_wait()
    ↓
    Poller获得事件
    ↓
    channel.SetRevents()
    ↓
    Channel处理

------------------------------------------------------------------------

## 3. TcpConnection

负责：
-   recv
-   send
-   输入缓冲区
-   输出缓冲区
-   业务逻辑

拥有：
    fd
    input_buffer
    output_buffer
    Channel

------------------------------------------------------------------------

# 三、为什么Poller返回Channel？
以前：epoll返回fd
问题：
fd：10
不知道：
-   谁管理它
-   如何处理

Channel：
包含：
    fd
    读回调
    写回调
    关闭回调

所以：
Poller：负责寻找对象。
Channel：负责处理事件。

------------------------------------------------------------------------

# 四、function和lambda实现回调

阶段六重点：反向调用。
以前：主循环调用TcpConnection
现在：
    事件发生
    ↓
    Channel调用callback
    ↓
    TcpConnection处理

例如：
TcpConnection：
``` cpp
auto read=[this]
{
    this->ReadHandler();
};
```

保存到：
``` cpp
function<void()> readcallback_;
```

事件发生：
``` cpp
readcallback_();
```

完成：
    Channel
        |
        |
    TcpConnection

------------------------------------------------------------------------

# 五、阶段六遇到的问题
## 问题1：events和revents混淆
错误：认为两个都是事件。

正确：
  变量        含义
  ----------- ----------
  events\_    希望监听
  revents\_   实际发生

关系：
    events_
    ↓
    epoll_ctl
    ↓
    内核监听

    发生事件
    ↓
    revents_

------------------------------------------------------------------------

## 问题2：EnableWrite为什么没有立即生效？
代码：
``` cpp
events_ |= EPOLLOUT;
```
只能修改Channel。
内核不知道。

解决：
必须：
    Channel修改状态
    ↓
    Poller.UpdateChannel()
    ↓
    epoll_ctl(MOD)
    ↓
    修改内核监听

------------------------------------------------------------------------

## 问题3：UpdateChannel作用
不是修改fd。
而是：
> 修改epoll监听该fd的事件集合。
例如：
之前：
    fd=10
    EPOLLIN
之后：
    fd=10
    EPOLLIN | EPOLLOUT

------------------------------------------------------------------------

## 问题4：fd从哪里产生？
流程：
    accept()
    ↓
    clientfd
    ↓
    TcpConnection(clientfd)
    ↓
    Channel(clientfd)
    ↓
    Poller.AddChannel()

Channel不是产生fd，而是管理fd。

------------------------------------------------------------------------

## 问题5：channels_初始化
错误理解：
需要提前初始化。
实际上：
``` cpp
unordered_map
```
默认为空。
添加：
``` cpp
channels_[fd]=channel;
```
即可。

------------------------------------------------------------------------

## 问题6：RemoveChannel错误
错误：遍历map删除所有元素。

正确：
删除指定Channel：
    Channel
    ↓
    fd
    ↓
    epoll_ctl DEL
    ↓
    erase(fd)

------------------------------------------------------------------------

# 六、完整事件流程
## 1.连接建立
    accept
    ↓
    clientfd
    ↓
    TcpConnection
    ↓
    Channel
    ↓
    Poller管理

------------------------------------------------------------------------

## 2.读事件
    epoll_wait
    ↓
    EPOLLIN
    ↓
    Channel
    ↓
    ReadCallback
    ↓
    TcpConnection::ReadHandler
    ↓
    recv
    ↓
    input_buffer

------------------------------------------------------------------------

## 3.发送数据
    Business
    ↓
    output_buffer
    ↓
    EnableWrite
    ↓
    UpdateChannel
    ↓
    监听EPOLLOUT

------------------------------------------------------------------------

## 4.发送完成
    WriteHandler
    ↓
    Write
    ↓
    output_buffer为空
    ↓
    DisableWrite
    ↓
    UpdateChannel
    ↓
    恢复只监听EPOLLIN

------------------------------------------------------------------------
