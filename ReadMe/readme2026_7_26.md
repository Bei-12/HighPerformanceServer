UDP 网络编程学习笔记

一、UDP通信目标

通过 UDP 实现客户端（Client）和服务器（Server）之间的双向消息通信。

实现目标：

Client 主动向 Server 发送消息

Server 接收 Client 消息

Server 获取 Client 地址

Server 回复 Client

Client 接收 Server 回复

最终实现：

Client                         Server

socket()                       socket()

sendto()  ----------------->   recvfrom()

recvfrom() <-----------------   sendto()

二、UDP基本概念

1. UDP特点

UDP（User Datagram Protocol，用户数据报协议）：

无连接

不需要建立连接

不保证可靠传输

数据以数据报形式发送

发送时必须指定目标地址

UDP通信模型：

发送方 socket
       |
       |
       ↓
   IP + port
       |
       |
       ↓
接收方 socket

三、Socket概念

1. socket是什么？

socket本质是一个文件描述符（fd）。

Linux中：

普通文件

管道

socket

都可以通过文件描述符进行操作。

例如：

int sockfd = socket(AF_INET, SOCK_DGRAM, 0);

返回：

sockfd
 |
 |
网络通信入口

2. 为什么Client和Server都需要创建socket？

错误理解：

Client创建socket，然后传递给Server。

实际：

两个进程拥有自己的socket。

Client进程                 Server进程

client_fd                  server_fd

    |                          |

自己的通信入口              自己的通信入口

socket不会传递。

两个进程通过：

IP + port

找到彼此。

五、socket()

函数：

socket(AF_INET, SOCK_DGRAM, 0);

参数：

AF_INET

表示IPv4。

SOCK_DGRAM

表示UDP。

TCP：

SOCK_STREAM

UDP：

SOCK_DGRAM

六、bind()

作用：

给socket绑定网络地址。

不是：

告诉系统数据发送到哪里

而是：

告诉系统这个socket负责哪个IP和端口的数据。

例如：

127.0.0.1:8080

绑定：

bind(sockfd, sockaddr, sizeof(sockaddr));

之后：

发送给：

127.0.0.1:8080

的数据会交给这个socket。

七、sockaddr_in结构体

网络地址：

struct sockaddr_in
{
    sin_family;
    sin_port;
    sin_addr;
};

对应：

协议族
+
端口
+
IP地址

例如：

server.sin_family = AF_INET;

server.sin_port = htons(8080);

server.sin_addr.s_addr =
inet_addr("127.0.0.1");

八、sendto()

作用：

将应用层数据交给操作系统网络协议栈，然后发送给目标地址。

流程：

应用程序数据

      |

sendto()

      |

Linux网络协议栈

      |

UDP数据报

      |

目标socket

函数：

sendto(
    sockfd,
    buffer,
    length,
    flags,
    target_address,
    address_length
);

UDP发送必须知道：

目标IP
目标port

九、recvfrom()

作用：

接收UDP数据，并获取发送方地址。

函数：

recvfrom(
    sockfd,
    buffer,
    length,
    flags,
    source_address,
    address_length
);

相比：

recv()

recvfrom多了：

发送方地址

因为UDP没有连接。

十、为什么Server需要保存client地址？

UDP没有连接：

client1
    \
     \
      server
     /
client2

Server收到数据：

hello

不知道来自谁。

recvfrom会返回：

数据

+

发送方IP

+

发送方port

保存：

sockaddr_in client_;

之后：

sendto(client_);

即可回复。

十六、遇到的问题总结

1. 为什么Client发送后阻塞？

原因：

recvfrom是阻塞等待。

如果Server没有回复：

Client会一直等待。

2. 为什么Server也需要socket？

因为socket是每个进程自己的网络入口。

不是传递socket，而是：

socket + IP + port

完成通信。

3. 为什么UDP不用listen和accept？

因为UDP没有连接。

TCP：

connect
listen
accept

UDP：

sendto
recvfrom

十七、UDP学习总结

通过UDP项目理解：

socket是网络通信入口

bind负责绑定IP和端口

sendto负责发送数据

recvfrom负责接收数据并获取发送方地址

UDP无需建立连接

Client和Server各自拥有socket

网络通信本质是通过IP和端口定位进程
