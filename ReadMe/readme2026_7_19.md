# 🍫 Functions & Concepts & Core Snippets

## 1. pthread_create()

作用：

创建新的线程并执行指定入口函数。

``` cpp
pthread_create(
    pthread_t* tid,
    const pthread_attr_t* attr,
    void* (*start_routine)(void*),
    void* arg
);
```

参数：

-   tid：保存线程ID
-   attr：线程属性，通常 nullptr
-   start_routine：线程入口函数
-   arg：传递给线程的数据

------------------------------------------------------------------------

## 2. pthread_join()

作用：

等待线程结束并回收资源。

线程生命周期：

    create
      |
      v
    running
      |
      v
    finish
      |
      v
    join reclaim

join 不负责控制执行顺序，只负责：

-   等待结束
-   回收资源

------------------------------------------------------------------------

## 3. void\* 参数传递

pthread 使用：

``` cpp
void* arg
```

传递任意类型数据。

例如：

``` cpp
Thread* t = (Thread*)arg;
```

恢复真实类型后访问对象。

------------------------------------------------------------------------

## 4. this 指针传递

为了让线程访问整个对象：

``` cpp
pthread_create(
    &_t,
    nullptr,
    Routine,
    (void*)this
);
```

线程函数：

``` cpp
Thread* t = (Thread*)arg;
```

可以访问：

``` cpp
t->_num;
t->_worktime;
```

------------------------------------------------------------------------

## 5. 为什么线程入口函数使用 static

普通成员函数：

    func(Thread* this, void*)

存在隐藏 this 参数。

pthread 要求：

    func(void*)

参数不匹配。

static 成员函数没有 this：

    func(void*)

因此可以作为线程入口。

------------------------------------------------------------------------

## 6. 多线程执行顺序

创建顺序：

    Thread1
    Thread2
    Thread3

不代表执行顺序。

线程调度由：

-   操作系统
-   CPU时间片
-   系统状态

决定。

三个顺序可能不同：

    创建顺序
    执行顺序
    结束顺序

------------------------------------------------------------------------

## 7. 对象生命周期问题

错误：

``` cpp
for(auto t : vT)
{
    t.Start();
}
```

原因：

auto 会复制对象。

线程保存：

    this -> 临时对象

临时对象销毁后：

线程访问非法地址。

解决：

``` cpp
for(auto& t : vT)
{
    t.Start();
}
```

保证线程使用真实对象。

# 🐛 Mistakes & Debugging Loops

## 问题1：所有线程显示 Thread 10

现象：

    Thread 10
    Thread 10
    Thread 10

原因：

for(auto t:vT) 创建对象副本。

解决：

使用：

``` cpp
auto&
```

------------------------------------------------------------------------

## 问题2：线程执行顺序混乱

原因：

线程调度由系统决定。

解决：

理解：

    创建顺序 != 执行顺序

------------------------------------------------------------------------

## 问题3：Join顺序和结束顺序不同

原因：

join 只是等待和资源回收。

不会控制线程执行。

------------------------------------------------------------------------

## 问题4：this指针访问失效对象

原因：

线程异步运行，对象可能提前销毁。

解决：

保证：

    对象生命周期 >= 线程生命周期

------------------------------------------------------------------------

# ❌ Ideological Misunderstanding

## 误区1：

创建线程越早，执行越早。

正确：

    创建顺序
    ≠
    调度顺序
    ≠
    结束顺序

------------------------------------------------------------------------

## 误区2：

this 是 pthread 的额外参数。

正确：

this 是 C++ 隐藏机制。

pthread 只接收：

``` cpp
void* arg
```

this 只是通过 arg 传递的数据。

------------------------------------------------------------------------

## 误区3：

join 控制线程执行。

正确：

join 只负责：

    等待 + 回收
