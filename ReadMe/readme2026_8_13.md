二、Epoll整体思路
Epoller职责
Epoller负责：
创建 epoll
添加fd
修改fd事件
删除fd
等待事件发生

核心思想：
epoll不负责处理数据，只负责告诉服务器哪个fd已经准备好。
流程：
创建epoll
    |
添加需要关注的fd
    |
epoll_wait等待
    |
返回发生事件的fd

四、遇到的问题与解决
问题1：event中的fd和sockfd关系
错误理解：
认为event fd和sockfd相同。
正确：
sockfd：
服务器监听socket
event.data.fd：
当前发生事件的fd
例如：
listenfd = 4
client1 = 5
client2 = 6
epoll返回6：
说明client2有事件。
通过：
fd == listenfd
判断：
accept
recv

问题2：Receive使用错误fd
错误：
Receive(sockfd_)
原因：
sockfd是监听socket。
监听socket只能：
accept()
不能：
recv()
解决：
使用：
events_[i].data.fd
获取当前就绪fd。

问题3：events数组下标错误
错误：
events_[ret]
原因：
ret表示事件数量。
例如：
ret = 2
有效：
events_[0]
events_[1]
不是：
events_[2]

问题4：返回局部变量地址
错误：
char* Receive()
{
    char buffer[];
    return buffer;
}
原因：
函数结束后局部变量生命周期结束。
解决：
使用：
string
管理数据生命周期。

问题5：recv缓冲区问题
错误：
接收全部4096字节后再添加'�'。
原因：
数组越界。
解决：
预留一个位置：
buffer大小4096
recv最多读取4095
最后保存

问题6：Bad file descriptor
原因：
删除了错误fd。
错误：
客户端fd事件
 |
处理sockfd
 |
删除listenfd
正确：
事件发生fd
 |
处理对应clientfd
