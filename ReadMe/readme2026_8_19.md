# 阶段六：Reactor服务器实现总结

## 一、阶段六目标
阶段六目标是将传统socket服务器升级为基于Reactor模型的事件驱动服务器。
核心思想：操作系统负责检测事件，服务器负责分发事件，对应对象负责处理。
整体结构：
    EventLoop
        |
        |
    Epoller(Poller)
        |
        |
    Channel
        |
        |
    TcpConnection

------------------------------------------------------------------------

# 二、Channel设计
## Channel作用
Channel是Reactor中fd的对象化管理。
负责：
-   保存fd
-   保存关注事件events\_
-   保存实际发生事件revents\_
-   保存回调函数

以前：fd -> epoll

现在：fd -> Channel对象 -> 回调 -> TcpConnection

------------------------------------------------------------------------

## events和revents
events：表示希望内核监听什么事件。

例如：EPOLLIN 表示关注读事件。

revents：表示内核实际返回发生的事件。

两者分离原因：events是用户告诉内核：我要关注什么；revents是内核告诉用户：发生了什么

------------------------------------------------------------------------

# 三、function和lambda回调

问题：
Channel知道事件发生，但是不知道如何处理。
例如：EPOLLIN 应该由TcpConnection负责recv。

所以使用回调：
    Channel
     |
    readcallback
     |
    TcpConnection::ReadHandler

lambda捕获this：保存当前对象地址，使Channel可以反向调用TcpConnection成员函数。

------------------------------------------------------------------------

# 四、TcpConnection设计

TcpConnection负责：
-   recv读取数据
-   send发送数据
-   输入缓冲区
-   输出缓冲区
-   连接关闭

结构：
    TcpConnection
     |
     + fd
     + input_buffer
     + output_buffer
     + Channel

------------------------------------------------------------------------

# 五、非阻塞IO
Read流程：
    recv()
    有数据
     |
    保存input_buffer

    没有数据
     |
    EAGAIN

EAGAIN表示：当前没有数据，不阻塞，等待下一次epoll通知。

------------------------------------------------------------------------

Write流程：
发送失败：EAGAIN

说明发送缓冲区满。

没有发送完的数据保存到output_buffer。

下一次EPOLLOUT继续发送。

------------------------------------------------------------------------

# 六、Epoller设计

Epoller负责封装epoll：
-   创建epoll
-   添加Channel
-   修改监听事件
-   删除Channel
-   等待事件

为什么Poll返回Channel？
因为epoll返回的是：fd + event

服务器需要：fd对应的对象

所以：fd -> Channel*

保存映射。

流程：
    epoll_wait
    ↓
    得到fd
    ↓
    map查找Channel
    ↓
    SetRevents
    ↓
    返回活跃Channel

------------------------------------------------------------------------

# 七、UpdateChannel意义
EnableWrite只修改：Channel.events_
但是内核不知道。
所以需要：
    UpdateChannel()

调用：
    epoll_ctl(MOD)

同步：
    Channel状态
    +
    内核监听状态

------------------------------------------------------------------------

# 八、EventLoop设计
EventLoop是Reactor核心。
负责：
1.  等待事件
2.  获取活跃Channel
3.  分发事件

流程：
    while(running)
    {
     Poll()
     Channel.HandlerEvent()
    }

EventLoop不负责：
-   recv
-   send
-   业务逻辑
只负责调度。

------------------------------------------------------------------------

# 九、阶段六遇到的问题
## 1. Channel直接依赖TcpConnection
问题：模块耦合。

解决：function + lambda。

Channel只保存回调，不知道具体处理对象。

------------------------------------------------------------------------

## 2. lambda立即执行
错误：创建lambda后直接调用。

解决：保存lambda：function<void()>

事件发生时调用。

------------------------------------------------------------------------

## 3. TcpConnection生命周期错误

错误：Accept中创建局部对象。

函数结束：
    析构
    close(fd)
连接断开。

解决：TcpServer保存Connection对象。

------------------------------------------------------------------------

## 4. EnableWrite没有更新epoll
错误：只修改events\_。

解决：调用UpdateChannel同步内核。

------------------------------------------------------------------------

## 5. accept只执行一次
问题：一次连接事件可能对应多个客户端。

解决：非阻塞accept循环，直到EAGAIN。

------------------------------------------------------------------------

# 十、TcpServer设计

TcpServer负责：
-   创建监听socket
-   bind
-   listen
-   accept
-   管理TcpConnection

流程：
    listenfd
    ↓
    Channel
    ↓
    Epoller
    ↓
    EPOLLIN
    ↓
    Accept
    ↓
    clientfd
    ↓
    TcpConnection
    ↓
    加入Epoller
